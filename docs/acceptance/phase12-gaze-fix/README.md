# Phase 12 保存后的视线控制修补

2026-10-04。原版保存在提交9fde536（游戏代码591e116），独立本机预览保持原构建。本轮在原开发分支继续修补，关联仍开放的 #7「真实注视事件、异常恢复与会话计时」。用户授权排查并修补实际无法移动的问题；只修改 A 眼动/训练逻辑和游戏的错误提示，不修改共享契约或场景地图，不伪装 B 审查。

## 已确认的代码问题和修补

- 三次失败免测入口会恢复最新未通过参数，再启用 basicEntry。旧管线只有缺失映射/分类器时才使用基础几何，因此已有但错误的模型会否决免测输入。现在基础模式始终使用真实眼部几何，保留相机有效性、全屏、稳定窗口与原始范围判断，不使用失败模型的基线或姿态范围限制基础模式。
- 有完整参数但屏幕分类验证未通过的显式体验入口仍依赖该失败分类器。现在这个入口用未裁剪的个人位置预测判断屏内外，仍保留坐姿覆盖与传感器检查；已通过的分类器继续控制已验证路径。未通过标记保留，不将体验描述为验证成功。
- 摄像头接受500ms以内的捕获结果，游戏和屏幕稳定器却按250ms拒绝/清空，300ms处理延迟或采样间隔因此不能控制行走。三者现在共享500ms上限。捕获时间不重写，不允许过期、未来或乱序输入；显式无效输入立即停步。低帧率情况下的可判断统计因此最多延长到相机已有的500ms寿命。
- 摄像头原先收到任何resize/fullscreenchange都会清空校准。现在仅在视口、屏幕尺寸、像素比例或全屏状态实际变化时清空。真正的环境变化仍需重新校准。
- 错误原因优先按当前入口授权和交互状态判断，避免在已允许免测时错误显示未验证。游览HUD分别提示眼部未识别、坐姿超范围、分类不确定、延迟、校准失效等具体原因，失去相机输入仍停步。

这是对可复现代码路径的修补；无法据此确定用户那一次运行触发了其中哪一项，也未做真人精度验收。
