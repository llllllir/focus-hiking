# 晴雨环境声音修补

2026-10-05。用户明确要求仅调整游戏声音。沿用 Phase 13 开发分支，在 B 游戏/场景音频范围作定向修改，组合入口仅添加音频解锁及释放；不修改眼动逻辑、运动、校准、地图、视觉天气规则或共享契约。Phase 13 保存点 `e128553` 保留。

## 改动与原因

- 自动进入发生在异步加载完成后，旧实现可能等待浏览器音频恢复却没有真实用户操作。现在在首页的真实点击/键盘操作内先创建和恢复音频，森林与天气共用一个输出；入口保留上下文，离开场景停止所有声源，卸载整个体验后释放上下文。恢复等待超时后显示“点击开启环境声音”，不冒充已播放，真实点击可重试。
- 声源初始化时立即同步相机位置与听者，避免首帧空间衰减误用原点。晴天复用既有本地鸟鸣、树叶与溪流录音，适度提高混音，录音做不超过8倍、峰值上限0.85的运行时响度归一化，原文件与许可保持不变。
- 初测只调整录音增益仍得到约0.0006–0.001的晴天输出RMS，安静片段仍偏小。因此增加原创、连续、柔和的树冠风声底音，并让附近叶声随听者位置更新；间歇鸟鸣改用音频时钟调度，避免低渲染帧率无限拖延叫声。
- 提高连续雨声、雨滴和雷声的混音，保留既有雷声时序及天气切换规则。晴天森林声音在雨天淡出到背景，不添加语言播报。
- 默认总音量80%，新增0–100%音量滑块，静音选择跨天气切换保持有效。共同输出增加动态压缩，控制叠加峰值。报告的声音来源更正为本地署名录音加原创合成。

声音库见[本地来源与许可](../../../public/audio/forest/CREDITS.md)，本轮没有下载新资源、安装插件或引入服务。浏览器启动处理参考[Chromium 官方自动播放说明](https://www.chromium.org/audio-video/autoplay/)：Web Audio需要根据实际运行状态确认播放，并在用户操作后恢复。

## 实际检查

检查脚本 `scripts/weather-audio-check.cjs` 通过真实浏览器AudioContext与实际解码的本地录音运行；视线仅为明确标记的合成装置，不使用真人摄像头或麦克风。输出采样通过AnalyserNode获取应用数字波形，不代表扬声器实际声压或真人听感。

[检查结果](checks.json)与[音量控件截图](controls-synthetic.png)记录晴天/雨天非静音、波形无削波、20%/80%电平变化、切换天气保持静音、重新播放及销毁关闭共享上下文。另用明确模拟的resume阻塞补测超时提示和真实点击恢复；此模拟不是对浏览器自然阻止播放的测量。原生首次运行可能已获播放授权，应以结果中的initial字段为准。

最终实际通过类型检查、63项既有逻辑测试、生产构建、7组音频浏览器检查、文档与差异检查；页面脚本错误0。默认80%数字输出RMS晴天约0.0456、雨天约0.0377，采样峰值分别约0.181/0.142；20%雨天RMS约0.0092，静音淡出后约0.0000094。测试没有降低初测电平断言。构建保留既有场景包体积提示。

另在生产预览的现有流畅档通过[2组入口检查](production-entry.json)：真实点击提前解锁共享音频，自动入场显示80%音量，回首页再进入复用同一上下文，无页面脚本错误。该装置明确种入合成三次失败资格，不能用于证明真人测试次数或眼动精度。初次装置假设的摄像头签名不匹配，改用固定合成设备ID；强制用户操作的浏览器测试参数又阻挡了合成摄像头播放，生产入口改用普通浏览器配置后通过。阻止音频恢复的行为仍由前述专用装置明确模拟并验证，不因此宣称所有平台自然自动播放都通过。
