# 真实摄像头眼动原型：实现与操作

后续升级已加入屏幕内外校准、独立状态验证、稳健特征和同页森林组合入口。当前操作请读 [升级接入说明](eye-gaze-integration.md)；以下保留最初原型的实现记录，18点流程、固定平滑及未接场景等描述不代表升级版本。

日期：2026-10-03。角色 A，分支 `codex/m2-attention`，对应 [M2-A #4](https://github.com/llllllir/focus-hiking/issues/4)。

## 当前交付

独立诊断入口 `/?mode=gaze-test`，真实摄像头 + 本地 MediaPipe Face Landmarker + Worker + 个人岭回归。中央球连续显示注视预测，左上角眼球示意显示双眼虹膜相对眼部的运动。未校准时只作明确标记的方向预览；该预览不向 AttentionPort 发布有效屏幕注视样本。

这是一项可运行实现，尚未完成真实摄像头精度、主观体验和多人验收。普通摄像头的特征稳定性、眼镜反光、低照度、头部移动和纵向精度须实际测试。

## 启动

Node.js 22.12+ 或 Node.js 24，仓库根目录：

```powershell
npm ci
npm run dev
```

打开终端打印的本地地址，并加 `/?mode=gaze-test`。眼动入口不加载森林模型。正常森林入口仍使用原有模拟诊断，本次没有把真实注视接到路径导航。

1. 点击「开启摄像头」，在浏览器允许访问。默认 CPU/WASM；GPU 为实验选项，必须分别实测后再选择。
2. 保持头部基本稳定、正面柔和光照，眼睛看左右。未校准的小球是方向预览，不代表已准确定位屏幕。
3. 点击「九点校准」。两轮随机顺序共18点，每点1.5秒，前0.4秒丢弃。当前纯采样约27秒。样本不足时停止并明确提示；重新校准，不用旧参数冒充成功。
4. 点击「五点验证」，注视未参与拟合的5个位置，纯采样约7.5秒。查看有效比例、中位/P90屏幕对角线误差，下载 CSV。
5. 校准后看左/右/上/下/中央固定标记，观察小球和眼球示意。不要追着移动的小球做方向验收。
6. 点击「停止」释放摄像头、终止 Worker 并清除校准。刷新页面也不保留参数。

校准和验证可以取消。后台切换取消当前采样；窗口变化清除校准；坐姿明显改变时停止接受屏幕交互并提示恢复或重校准。实际采样要求保持浏览器窗口及坐姿稳定。

## 实现与接口

- `src/attention/features.ts`：按官方左右眼/虹膜索引，在未镜像的摄像头像素中建立眼部局部轴；按眼宽和眼高归一化，提取双眼位移、开放程度、头部姿态、脸部位置及尺度。矩阵采用 MediaPipe 的列主序，并剔除缩放影响。头部角度是模型估计，眼球图的角度是示意值。
- `src/attention/gaze.worker.ts`：VIDEO、单人脸、面部变换、阈值0.6；同步模型调用全部在模块 Worker。使用 tasks-vision 1.0.1 的 ES模块 WASM 加载路径。目标浏览器为支持 SIMD、Worker、ImageBitmap 和 OffscreenCanvas 的桌面 Edge/Chrome；其它环境未验证。
- `src/attention/camera.ts`：15Hz调度，忙时跳过采集，不排旧帧；消费结果时检查帧年龄500ms，推理挂起10秒停止；每次结束关闭 ImageBitmap。浏览器媒体权限异步请求不能由网页强制取消，晚到的授权流会立即停止，不启动旧会话。
- `src/attention/regression.ts`：标准化特征、分别拟合x/y、按校准目标留一分组选择岭系数。独立五点验证不参与拟合或调参。
- `src/attention/measurement.ts`：65ms时间常数平滑；信号失效重置。误差使用平滑后未经裁剪预测、CSS像素距离/视口对角线。屏幕外预测计入误差，但禁用交互。
- `src/attention/test-page.ts`：方向预览、小球、眼球示意、两轮校准、独立验证、匿名CSV。每个验证点计划17个采样时段，丢失时填 `missing-sample`，不从有效率分母剔除。

`CameraAttention` 实现既有 `AttentionPort`，样本来源 `camera`，可订阅样本/事件并设置目标区域；复用现有1.2秒 DwellTracker。无有效映射时x/y为null。原始超界预测不裁剪成有效边缘选择。共享契约没有字段变化。眼球特征仅在A诊断内部使用，没有暴露给B。

诊断中的「帧提交至结果」包括 ImageBitmap 建立、传输、排队和处理，不包括摄像头曝光/设备缓冲和绘制完成，不能作为眼睛到画面端到端延迟。推理频率是完成结果频率，不是摄像头FPS。CPU/GPU、真人性能与联合森林负载均须分别测量。

## 资源与隐私

资源位于 `public/models/mediapipe/`；[manifest](../public/models/mediapipe/manifest.json) 记录固定包版本、Google模型版本1、体积、来源与SHA256；附带上游代码许可。代码为Apache-2.0；[官方Face Mesh V2模型卡](https://storage.googleapis.com/mediapipe-assets/Model%20Card%20MediaPipe%20Face%20Mesh%20V2.pdf)第一页同样明确Apache-2.0。模型来源与模型卡单独记录，不把这一项核查扩大为整个bundle所有组件条款均已核验。

正常运行不访问第三方CDN。资源重建需联网：

```powershell
npm run assets:gaze
```

脚本从已安装包复制 WASM，从 Google 官方版本地址下载模型；已有manifest中模型哈希若变化则拒绝覆盖。模型和运行时资源可随应用提供，发布前仍应核对模型发布条款。

摄像头帧只在浏览器内短暂处理，不写磁盘、不上传。校准样本与参数仅在内存；CSV由用户主动下载，只包含注视坐标、目标、状态、视口和耗时，无面部图像、原始特征或身份。自动化检查只使用合成夹具，不能作为camera真人测量。

## 原型验收与M2边界

本次原型检查建议：左右各10次随机提示，方向正确至少18/20；上下与回中对应移动；连续扫视无固定档位跳变；中央注视10秒记录抖动；闭眼/离开/后台暂停并恢复；头眼区分；分别记录推理Hz、P95处理耗时和另行测量的端到端响应。方向、抖动与响应建议值不替代原M2门槛。

M2维持原要求：至少4人、至少3人中位误差≤8%对角线、P90≤15%、有效率≥90%、区域成功≥80%、20次停留正确≥85%、5分钟自由观看误触发≤1。三大目标界面、场景路标消费及联合验收继续按B与共同验收Issue交接。没有真人数据时保持Issue/Milestone打开。

实际命令和检查结果见 [原型验收记录](acceptance/gaze-prototype/README.md)。
