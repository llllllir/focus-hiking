# Focus Hiking：最终双人、双 Agent 开发计划

基线日期：2026-10-02。导师确认的分工：A 做注视与训练并建立主仓；B 做场景并作为 collaborator 加入。两人分别使用 agent 开发，每阶段分别提交和合并各自 PR。

## 1. 目标与现状

交付电脑端虚拟登山游戏：屏幕呈现森林环境，摄像头在本地估计注视区域，通过注视路标、观察任务和温和事件构成训练体验。选择 5/10/15 分钟，结束后给出本次表现记录。

今天先做出可看的场景；M2 必须做出真正的摄像头注视系统；M3 联动，M4 完成训练闭环，M5 真人试用。当前应用未实现，研究和计划不等于可运行系统。

两名负责人：A = llllllir（主仓、注视、训练、记录），B = RUI-TW（场景、游戏、交互、性能）。导师确认阶段通过。没有假设两个 agent 自动互相通信：交接以接口文档、GitHub Issue/PR 和 main 提交为依据。

现有研究主要讨论真实户外，不能直接证明电脑模拟登山有效。摄像头注视是行为线索，不是心理注意力或临床诊断。

## 2. 硬件与技术决策

| 项目 | 核查结果 | 决策 |
| --- | --- | --- |
| 电脑 | Lenovo 83DG，Windows 11 Pro | 首先在本机 Edge 验收 |
| CPU | i7-14700HX，20 核、28 线程 | 轻量本地推理，实测联合负载 |
| 内存 | 15.70 GiB，检查时约剩余 6.1 GiB | 控制素材和工具占用 |
| GPU | RTX 4060 Laptop，8188 MiB 显存；另有 Intel UHD 和虚拟显示设备 | 记录浏览器实际适配器，不保证已使用独显 |

| 摄像头 | Integrated Camera，设备状态正常 | 分辨率、帧率和精度尚待实际测试 |

技术栈固定为 TypeScript、Vite、Three.js。使用单张风格化森林地图，含营地、溪流、山顶远景；用植被、雾、光照和环境音建立氛围。今日交初步版，M4 细化同一地图。

注视使用本地 MediaPipe Face Landmarker + 虹膜/眼部几何 + 头部姿态 + 个人岭回归映射。模型与 WASM 本地提供，Worker 推理、最新帧策略。初始摄像头申请 640×480/30FPS，目标推理 15Hz、最低 10Hz。反馈为规则，第一版不接 LLM。

目标：场景单独争取 60FPS，联合至少稳定 30FPS；推理处理耗时 P95 ≤120ms。处理耗时与端到端响应分别测量。不达标先降低阴影、植被及分辨率，再比较 CPU/WASM 与 GPU delegate；浏览器 GPU 推理不等于 CUDA。

后续日期按持续投入估算，若可用工时改变就调整日期，不降低门槛。每个 Milestone 两人分别交付 PR，由对方审核后各自合并，再验收整版。

### M1：今天必须看见场景

A 先用约 45～60 分钟完成最小工程、共享接口和运行说明，提交基础 PR。B 同时准备场景，基础合入后接入。A 再交模拟信号/诊断 PR，B 交场景 PR。工程基础在前，后续两项并行开发并交叉审核。

场景初步时间预算为开工后 3～5 小时。提供自动游览，不让摄像头校准阻塞导师看场景。必须支持暂停、重启；提交截图、30～60 秒演示、加载时间、实际 GPU 和帧率。打不开或路径无法完成则 M1 不通过。模拟输入标记来源，不能用于 M2 验收。

### M2：交付真实注视系统

A 实现九点、两轮校准；每点约 1.5 秒，丢弃最初 0.4 秒；以未用于拟合的五点验证，报告有效率、中位/P90 误差。B 实现可独立使用的测试页、三个大目标、停留进度和无效提示。

至少 4 名测试者、至少 3 名达到：中位误差 ≤屏幕对角线 8%，P90 ≤15%；正常正面光照下有效采样率 ≥90%；三个大区域选择成功率 ≥80%；20 次停留正确率 ≥85%；5 分钟自由观看误触发 ≤1 次。这些是产品门槛，不是医学标准。

无效样本单独报告，区域失败不能从分母排除。摄像头拒绝、无人脸、眼部不可用、姿态越界和窗口变化都有状态。鼠标/模拟不能替代真实验收。未通过先排查坐标、镜像、采样与校准，再比较替代模型；M2 保持打开。

### M3：联动与联合性能

注视大路标约 1.2 秒确认。B 在移动期间锁定下一次选择，移动完成才重新开放。A 遇信号失效或切后台暂停注视交互，恢复后重新稳定停留。自由观景不触发分心规则。

双方完成一次 15 分钟真实摄像头旅程，记录帧率、推理频率、推理耗时和端到端响应。稳定 30FPS 与至少 10Hz 是联合运行底线，未通过继续优化而非直接推进 M4。

### M4：训练闭环

A 定义观察、等待目标、注视确认和结束回忆任务；B 用环境/UI 表达。事件用短暂起雾、落叶遮挡标识、溪流改道等温和变化，避免惊吓、强闪烁和惩罚。

只有任务窗口内有效信号持续离开目标才触发重新聚焦。初始离开阈值约 3 秒，冷却 ≥60 秒；5/10/15 分钟上限 2/4/6 次，由 M3 数据调整并记录理由。传感器失效暂停判断。

记录并展示任务完成率、目标命中率、有效任务时间、恢复次数、回忆回答和主观体验。不输出无依据的注意力提升分数。原始图像不保存、不上传；本地记录可查看和删除。

### M5：试用与决策

先做 4～6 人可用性测试并修复阻断问题，再做约 8～12 人固定/自适应模式探索对比，平衡体验顺序，保持地图和难度一致。记录误触发、完成率、挫败感、舒适度和再用意愿，单独报告传感器失效。

这个规模用于发现问题，不能证明长期注意力提升。报告决定继续完善、调整交互还是比较模型；训练迁移效果需要另行设计更长周期和独立注意力任务。

## 4. 模块与接口

A 独占 `src/attention/`、`src/training/`；B 独占 `src/scene/`、`src/game/`。共享 `src/contracts/` 由 A 初始定义，B 审核；后续先做双方认可的契约 PR。配置和锁文件由 A 管理。

接口包含 GazeSample、TargetRegion、GazeEvent、SceneEvent、TrainingCommand。坐标是游戏 CSS 视口左上角原点的 0～1 坐标。B 提供路标投影区域和是否允许选择；A 输出有效注视与停留事件。B 负责移动状态机，A 负责训练规则、记录和事件触发。[接口细则](interfaces.md) 为双方实现依据。

各自 clone/worktree，不同时编辑一个目录。Agent 不假设对方未合入内容存在，先读取 main 和交接文档。

## 5. GitHub 和 Agent 工作标准

A 建主仓，邀请 RUI-TW。B 接受邀请后才具备协作权限。5 个 Milestone 每个 3 个 Issue；标签区分 owner、stage、implementation/acceptance 与 blocked。

每阶段分支为 `codex/mN-attention` 和 `codex/mN-scene`。A 的 PR 由 B 审查，B 的由 A 审查。检查与审批通过后各自合并。默认先契约/注意力，再更新场景分支并合并。只有初始文档建仓可直接建立 main，后续不直推。

两项合入后共同验收，导师确认后 A 关闭 Milestone 并发布版本。每版都要两项合入 PR、运行说明、演示、实测、已知限制；逾期不能代替验收。

每次给 agent 的任务包写明角色、Issue、main 基线、允许修改范围、冻结接口、必须实现的行为、实际检查命令和明确不做的内容。Agent 读规则→查现状→实现→检查→PR→交接。摄像头真人测试、体验和导师验收由人完成。

不得擅自换模型、改门槛、跨模块重构或伪造测量。接口冲突先提出契约变更，继续无关工作。交接说明包含实现结果、命令与结果、接口变化、演示、剩余问题和另一方接入注意事项。

## 6. 检查与版本完成

自动化检查覆盖坐标映射、停留确认、重复事件防护、信号失效暂停和训练规则；场景视觉、摄像头精度和主观体验由人工验收。初始化 CI 只查文档，M1-A 建应用后增加类型检查和构建，不能把文档 CI 通过当成功能通过。

首版不做导航、社交、排名、多地图或手表接入。继续沿用 [研究报告](research.md) 和 [本地注视方案](gaze-system.md)；本计划替代仓库根目录的历史开发计划。
