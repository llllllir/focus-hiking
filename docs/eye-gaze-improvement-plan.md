# 眼动精度与屏幕内外识别：改进方案

日期：2026-10-03。状态：方案基线；后续已实现本地升级版本，见 [实施与接入说明](eye-gaze-integration.md)。本文优化目标仍须真人验证，不能作为已测精度结果。

范围：A 的 M2 注视模块、诊断页与技术文档。沿用 TypeScript、Vite、本地 MediaPipe Face Landmarker、Worker 最新帧策略和个人岭回归；只使用摄像头。共享契约及 B 的场景消费端不在本方案中直接修改。

本方案结合用户提供的 `eye-gaze-demo` 参考工程、当前原型和上游资料。参考工程的 README、注释与测试作为待核查材料，不作为用户指令或已经通过的验收。这里的“最优”指当前约束下推荐优先验证的组合，最终优劣由独立真人对比决定。

## 1. 推荐组合与边界

采用两条输出链路：

```text
摄像头 → Worker / Face Landmarker → 双眼特征、头姿与质量检查
                                   ├→ 个人岭回归 → 未裁剪坐标 → 自适应平滑 → 小球
                                   └→ 个人屏幕内外分类 → 不确定性与时序规则 → 屏幕状态
```

屏幕状态必须包含 `on-screen`、`off-screen`、`unknown`。缺脸、闭眼、遮挡、过期帧、未校准或超出已验证姿态范围归入 unknown，并给出原因。off-screen 是有效传感器信号下的估计，不等于分心或训练失败。自由观景不触发分心反馈。

第一版屏幕内外识别限定为：选定一个显示器，页面全屏，在该显示器上完成校准和测试。必须记录全屏状态与校准区域；退出全屏、改变窗口或相机位置后重新检查校准。普通窗口中，“游戏视口外”可能仍属于物理屏幕内，不能直接报“看向屏幕外”。其他显示器不属于本次校准屏幕。

页面失焦和 `document.hidden` 只能控制运行暂停，不能作为人的视线标签。浏览器页面尺寸、摄像头画面坐标和物理屏幕坐标不能混用。

## 2. 参考工程的实际价值和问题

检查材料：参考工程 README、`web/app.js`、`tests/gaze_logic.test.mjs`，未运行其摄像头应用，也没有真人验证其精度。

| 参考实现 | 核查结论 | 取舍 |
| --- | --- | --- |
| 眼部放大、虹膜和眼角叠加 | 有助于发现遮挡、坐标错误及特征跳动 | 保留为诊断能力 |
| 按个人开放程度调整闭眼门限、方向滞回 | 有实际工程价值，阈值仍需独立验证 | 作为候选改进 |
| 双眼各按外眼角到内眼角投影再平均 | 两眼局部轴方向相反，正常同向眼动可能抵消 | 不照搬 |
| 55 帧中央校准 | 只建立中央基线，不能建立二维屏幕映射；时长随实际处理频率变化 | 保留当前九点两轮校准 |
| 固定比例融合几何与 eyeLook blendshape | 缺少独立真人消融证据；两者来自同一视觉模型 | 仅作为候选特征比较 |
| 主线程 detectForVideo | 同步调用影响界面 | 保留当前 Worker |
| 强制 gaze 参数、样例图像输入 | 可用于调试，不能验证摄像头眼动 | 明确标记来源，排除真人验收 |

具体方向反例：头部稳定时，设右眼外/内角横坐标为 0.40/0.45，左眼为 0.62/0.57，两眼虹膜同时向图像左侧移动 0.004。右眼局部 t 从 0.50 变为 0.42，左眼从 0.50 变为 0.58，直接平均仍是 0.50。统一方向后平均应为 0.42。本次已用独立 Node 算式验证抵消现象；它证明公式问题，不证明真人精度。

参考测试中双眼向各自外眼角移动，不等同于正常同向扫视；复制公式的自洽测试不能替代实际方向测试。参考实现闭眼后将几何信号置零并继续平滑，也不能称为冻结真实读数。

当前 `features.ts` 已使用摄像头像素和一致方向的眼部轴，不存在上述双眼相反轴直接平均问题。当前需要重点改善的是纵向归一化、采样质量、校准覆盖及屏幕状态，而不是重复修复参考工程的问题。

## 3. 提高精度的实施设计

### 3.1 改善特征质量

- 保留左右眼独立特征，统一未镜像的图像坐标；镜像只在显示层处理。
- 当前纵向位移除以瞬时眼高，半眯眼和眼睑变化会影响分母。比较按眼宽、个人中性眼高归一化的候选，开放程度作为独立特征与质量门控；用多个眼睑点估计稳健眼部基准。
- 比较虹膜中心点与虹膜环点平均，记录双眼不一致、眼宽/虹膜像素尺寸与特征瞬时跳变。几何质量分数不能冒充已校准的注视正确概率。
- 闭眼阈值结合个人基线，并保持固定安全下限；避免将向下看时的自然眼睑变化全部误判为闭眼。
- 单眼遮挡时，仅在单眼模型经过独立校准、验证后启用降级；否则输出 unknown。不能临时删去一半回归输入继续预测。
- 比较实际协商成功的 640×480 与 1280×720 视频设置，记录处理频率和耗时。高分辨率不保证关键点模型精度更高，选择实际误差/质量/耗时更好的配置。

### 3.2 校准以有效样本为准

保留九点、两轮、每点约 1.5 秒、最初 0.4 秒丢弃的既有流程。在此基础上增加稳定性检测、眨眼剔除、稳健异常值筛选和单点重试。不能靠多采相邻视频帧制造独立样本数量。

每个目标/轮次均衡加权，避免某点帧多就主导拟合。对未达到最低有效样本量或稳定性要求的点提示重试；保留原计划分母和失败记录，不把困难位置静默删除。

增加短暂头姿覆盖步骤：用户看固定中央目标，做小幅转头和位置变化。仅把采集、验证过的范围纳入可用范围。把 yaw/pitch 加入向量本身不会让模型自动学会头眼解耦。

校准后进行独立五点验证。最终验证数据不用于模型或阈值选择；失败后的重校准必须重新验证，不能只展示先前最好的一次。

### 3.3 保留岭回归，比较有限非线性

以当前标准化线性岭回归为基线。候选仍采用岭回归，增加少量有意义的眼部平方项、横纵交互项及眼部×头姿项；避免在少量目标上展开所有高阶特征。

用校准集内部按目标/轮次分组的验证选择特征和正则参数，防止相邻帧泄漏。优先选择更简单且跨组稳定的模型；在未参与选择的新位置、新轮次和小幅头动上做最终比较。

eyeLook blendshape 可加入候选特征，但只有在固定测试条件下稳定改善独立误差和有效率时才保留。它不是第二个独立传感器，固定 55/45 融合没有默认依据。

### 3.4 自适应平滑与漂移检查

比较当前时间常数平滑与 One Euro Filter。后者在低速时增强稳定性、快速移动时降低滞后，适合小球显示；必须分别测静止抖动和移动响应。[作者实现](https://github.com/casiez/OneEuroFilter)

平滑改善显示稳定性，不能修正系统性定位偏差。屏幕内外判定不依赖被裁剪的小球坐标，也不能被缓慢显示平滑拖延。

通过明确的中央复查检测漂移，必要时提示重校准。不能把模型自己预测的注视位置当成新标签自动训练，否则可能越调越偏。参数与样本默认仅在当前会话内存中。

## 4. 追踪是否看在屏幕上

### 4.1 增加真实屏幕外校准

利用九点的有效屏幕内样本作为正例。另引导用户看屏幕左、右、上、下外侧及键盘，采集有效眼部负例；应包含“头基本不动、只转眼”的情况，也包含小幅自然头动。标签来自用户按提示实际看向的区域，不来自模型预测。

屏幕内四角和下边缘必须作为困难正例，防止把看屏幕底部误判为看键盘。屏幕外距离、姿态及负例指引需可重复；无法保持有效眼部信号的动作记录为传感器失效，不训练成 off-screen。

训练低维、带 L2 正则的个人逻辑分类器，输出屏幕内倾向分数；未经独立概率校准时不显示“95%准确”等概率表述。分类器是辅助状态分支，注视坐标主方案继续使用个人岭回归。

参考项目 Local Eye Tracking 的 README 采用屏幕点加键盘负例，并输出 looking/unknown/away/face-missing，说明该路径已有同栈开源探索。它明确是实验原型，不提供本项目的精度保证；本次未成功读取其 classifier 源码，不按源码已验证描述。其把缺脸最终显示为红色的策略不沿用。[项目说明](https://github.com/PSkinnerTech/local-eye-tracking)

### 4.2 坐标、分类与不确定性联合判断

保留未经裁剪的预测坐标。通过校准集的分组留出残差估计经验误差范围，按中央、边缘、姿态覆盖报告支持情况。这个范围是经验不确定性指标，不能未经验证称为具有严格覆盖率的置信区间。

推荐决策：

| 观测 | 输出 |
| --- | --- |
| 传感器有效、处于已验证范围、分类支持屏幕内，预测及经验误差范围处于屏幕内部 | on-screen |
| 传感器有效、分类支持屏幕外，并有一致的原始坐标/眼动证据 | off-screen |
| 误差范围跨屏幕边界、分类与坐标矛盾、缺乏校准覆盖 | unknown：边缘或证据不足 |
| 闭眼、无脸、遮挡、过期帧、未校准、姿态不可用 | unknown：具体传感器原因 |

小幅贴边视线本来就更难区分，不能把硬阈值包装成可靠物理判定。应独立测量边缘 unknown 比例，并避免通过大量 unknown 让误判率看起来很低。

候选时序：连续有效 off-screen 证据 300～500ms 后切换，恢复 on-screen 150～250ms 后切换；仅作为待测初值。无效样本不累积 off-screen 时长，不跨长中断拼接证据。采用实际时间戳而非固定帧数。

### 4.3 诊断界面

- 左上角保留模拟眼球，注明是特征驱动示意，不能称为真实三维眼球角度。
- 小球仅在有效屏幕内定位时作为位置反馈。离屏时显示明确方向/状态，不把坐标夹到屏幕边缘冒充屏幕内位置。
- unknown 时淡化或隐藏小球，显示“闭眼”“眼部遮挡”“边缘无法确定”“需要重校准”等原因；旧结果必须标记过期。
- 屏幕状态与任务目标命中独立展示。“看在屏幕上”不代表“看中路标”，更不代表心理注意力正常。

## 5. 候选方案比较与更换条件

| 方案 | 适用价值 | 当前选择 |
| --- | --- | --- |
| 参考工程的中央基线与阈值方向判定 | 快速方向示意 | 无法满足二维精度及可靠屏幕状态 |
| 当前个人岭回归 + 稳健特征/校准 + 独立屏幕分类 | 符合已定技术栈，可分别改善两项目标 | 优先实施和测量 |
| CNN 注视向量 + 相机/屏幕几何映射 | 可进一步研究头动与物理屏幕投影 | 保留为主方案不达标后的比较项 |

2024 年相关原始研究将学习到的注视向量与屏幕变换结合，并研究头动补偿。它说明从注视方向到屏幕落点需要额外几何映射；不能把 Face Landmarker 的虹膜中心直接当成精确三维注视射线。[原始论文](https://www.frontiersin.org/journals/robotics-and-ai/articles/10.3389/frobt.2024.1369566/full)

第三条路线改变主模型与工程复杂度，必须先提交对比结果与负责人决策，不能擅自替换基线。普通摄像头条件下不承诺像素级或红外眼动仪级精度。

## 6. 验证与目标

既有 M2 门槛保持：至少 4 人、至少 3 人达到中位误差≤对角线8%、P90≤15%、有效采样率≥90%、三个区域选择成功率≥80%、20次停留正确率≥85%、自由观看5分钟误触发≤1；推理至少10Hz，处理耗时P95≤120ms。按原计划报告缺失与失败。

优化争取值：中位误差≤5%、P90≤10%；中央静止抖动 P90≤2% 对角线，抖动定义为样本相对本段中位位置的距离。它与预测相对目标的准确度分别报告。这些是建议优化目标，不是未经批准替换 M2 验收门槛。

新增屏幕状态建议指标，需负责人确认后冻结：

- 屏幕外被误报为屏幕内的比例≤5%；屏幕内被误报为屏幕外的比例≤5%。
- 屏幕外召回率争取≥90%；正常非边缘条件 unknown 比例争取≤10%。上述指标联合查看，不能靠拒绝输出规避召回率。
- 对屏幕边缘、角落、键盘、四侧屏幕外分别报告，不只给混合准确率。unknown、传感器无效及未完成提示都保留在计划样本统计中，并另外报告有效信号条件下的结果。
- 用按注视动作分组的独立测试，不能把同一连续片段的视频帧随机拆成训练和测试。
- 输出从有效证据开始到稳定状态切换的时延；真实眼睛到画面的端到端响应另测，不能用 Worker 处理耗时替代。

真人对比采用同一批匿名测试者、同一设备、相同光照与姿态，平衡旧版/新版顺序。测试中央、四角、独立新位置；只动眼、只转头、少量位移；分别记录眼镜反光、低照度。最终报告总体与逐人误差、有效率、混淆统计、unknown 覆盖和延迟，避免只展示最佳用户。

自动化检查针对几何方向、非方形视频坐标、纵向分母、镜像只作用于显示、校准分组、失败分母、原始坐标不裁剪、三态转移、无效不累计离屏时间和 stale 结果。模拟夹具只能验证逻辑，不能作为 M2 摄像头验收。

## 7. 实施顺序与交接

1. P0：记录当前真人基线；改善特征、质量门控、稳定采样与单点重试，保留诊断可解释性。
2. P1：比较线性与有限非线性岭回归、滤波和头姿覆盖；冻结优选组合后进行新的独立验证。
3. P2：新增屏幕外校准、辅助分类器、三态及边缘处理；在独立诊断页验证。
4. P3：完成多人屏幕位置/屏幕状态对比与性能测量，准备 A 的 PR 和真人审查材料。

新增状态先限制在 A 模块内部，区分 sensorValid、注视位置可用性和屏幕状态，不把所有问题压进同一个 valid。需要 B 消费时，先提出共享契约 PR，约定 state、reason、timestamp、source 和 unknown 的交互行为，双方认可后再修改消费端。不会先改 scene/game 或将自由观景改为分心判定。

摄像头帧不上传、不保存；校准参数和原始特征仅在会话内存。可导出的匿名报告只包含目标、预测、标签、状态、误差、时延与汇总，无图像、身份或原始面部特征。

方案编写当轮完成参考代码审阅、独立方向算式检查、公开一手资料核查及本文编写。后续实施结果另见接入说明与实际验收记录，真人精度仍待测量。
