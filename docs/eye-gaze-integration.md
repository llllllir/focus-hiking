# 眼动升级与场景接入

本次实现沿用本地 MediaPipe、Worker 最新帧、个人岭回归和冻结的 AttentionPort。角色 A，分支 `codex/m2-attention`，对应 M2-A #4。新增状态仅在 A 模块内部，没有修改共享契约或 B 的 scene/game 源文件。

## 直接演示

```powershell
npm ci
npm run dev
```

使用终端给出的地址：

- `/?mode=gaze-scene`：校准、验证后进入现有森林，通过真实摄像头注视目的地。
- `/?mode=gaze-test`：独立小球、左上角眼球、三大目标交互诊断。

摄像头、模型和校准参数在同一页面会话中保留。进入森林不刷新、不换页面，因此不用重新校准。停止、刷新、显示区域变化会清除校准。

诊断面板可勾选本地眼部放大，显示当前视频眼部裁剪及虹膜中心叠加；关闭或停止时清空画布，不导出眼部图像。叠加用于排查，视频与关键点有处理时差，不能作为精度真值。

1. 进入全屏，再开启摄像头。先确认方向预览与眼球示意随眼睛移动。
2. 九点校准：两轮九点，另有两轮各四个中央小幅头姿步骤，共26段。头姿步骤读完提示后点击“开始此项”，眼睛仍看中央点。每段1.5秒，前0.4秒不采样；不稳定点最多自动重试两次。
3. 五点验证：五个未用于拟合的位置，约7.5秒。低有效率和较大误差会阻止进入交互。
4. 屏幕内外校准：两轮各五个屏幕内位置、五个屏幕外方向，共20段。屏幕外提示读完后点击开始，注视指定物理位置直到短提示音；双眼需留在摄像头中。屏幕内点包含四角，负例包含四侧和键盘。
5. 屏幕状态验证：10段独立采样，屏幕内目标换为未参与拟合的位置，屏幕外重新按提示采样。界面报告误报、召回及无法判断比例。
6. 两项验证通过后，点击“进入森林交互”；进入森林，切换“路线规划”，注视目的地约1.2秒。移动期间由既有场景状态锁定下一次选择。也可返回校准做中央复查。

屏幕外提示无法在网页中显示真实物理目标，必须由测试者按指引实际看向对应位置。指导标签不是独立眼动仪真值，结果用于本项目可用性验证。

## 处理与交互语义

`features.ts` 使用未镜像像素坐标、一致眼轴和眼宽归一化纵向位移；眼睑开放程度单独判断。低像素眼部、闭眼和双眼不一致输出无效。

`calibration.ts` 提供中位数/MAD稳健筛选、个人开放程度阈值和经验姿态覆盖。坐姿覆盖来自实际采样的5%～95%范围加固定容差，不是对任意头动的保证。

`regression.ts` 按目标与轮次均衡加权，按目标留一比较线性与有限二次特征岭回归。仅校准数据选择正则与模型；复杂模型需至少约10%的内部误差改善才能取代线性模型。独立验证不参与拟合。分组留出残差给出经验边缘余量，不能解释为严格95%置信区间。

`screen.ts` 使用带L2正则和眼部二次项的个人分类器，按整轮留出检查区分度。结合未裁剪预测、经验余量、姿态覆盖和全屏状态输出三态；模型分数不显示为准确率。on-screen连续有效证据200ms、off-screen400ms后稳定，unknown立即打断确认；超过250ms间隔及时间倒退清空积累。

`pipeline.ts` 将传感器有效、可用位置、屏幕状态和交互许可分开处理。只有位置验证、屏幕状态验证通过，且当前屏幕状态为on-screen、坐标可用、交互已启用时，才发布 `GazeSample.valid=true`。其它情况发布无效样本，既有DwellTracker清空停留。坐标测量使用独立 `position`，不会因交互未启用而丢弃真实定位误差。

`filter.ts` 使用One Euro自适应平滑绘制位置。屏幕分类消费未裁剪、未被显示平滑拖延的坐标。失效小球隐藏；未完成屏幕分类的坐标预览明确标记为预览，不能控制场景。

屏幕分类正例还复用本次九点和小幅头姿校准的有效样本，并保留轮次分组；这些特征仅保留在当前会话内存。这样屏幕分类的姿态覆盖不会无故退回单一正脸姿态。

当前位置验证门槛沿用有效率≥90%、中位误差≤8%对角线、P90≤15%。新增屏幕交互启用条件：两方向误报各≤5%，屏幕内/外召回各≥90%，unknown≤10%。这些是此次功能启用条件；不代表M2多人、停留和联合性能已验收，也不将优化目标5%/10%冒充已达到。

## B 的接入方式

本地组合入口 `scene-session.ts` 已调用现有 `mountGame(scene, camera)`，B 的可选AttentionPort参数无需改形状。场景继续提交归一化TargetRegion及enabled，并订阅原有GazeEvent；B不需要接触眼部模型或校准样本。

```ts
// 在当前会话完成校准及独立验证后：
const game = mountGame(sceneContainer, cameraAttention);
cameraAttention.setInteractionEnabled(true);
// 场景负责setTargets和既有移动/暂停期间enabled=false。
// 摄像头模块自动使屏幕外、unknown、闭眼、过期信号失效。
```

摄像头类还提供A内部诊断订阅 `subscribeUpdates`、`subscribeScreenStatus`。B若需要将三态作为正式产品接口消费，仍须另做契约PR。不要把内部特征依赖扩散到共享contracts。

新增无效原因包括 `screen-not-calibrated`、`screen-unverified`、`position-unverified`、`screen-uncertain`、`screen-settling`、`fullscreen-required`、`eyes-disagree`、`interaction-paused`。旧消费者只依赖valid=false即可停止停留，无需识别新字符串。

场景既有运行报告中的 `cameraImplemented:false` 是B旧版静态字段；联合入口实际连接情况由 `cameraInputConnected` 和事件来源核对。该报告字段需要B在自己的PR维护，不能用其旧值解释A实现状态。

## 数据与验收

不上传或保存摄像头帧。校准特征和参数仅在内存；导出只包含匿名目标、预测、状态、误差/时间数据。窗口、全屏状态变化后清除校准。普通窗口的视口外不等于物理屏幕外。

实际命令、浏览器检查及未完成真人项目见 [本轮验收记录](acceptance/gaze-upgrade/README.md)。新旧模型、视频分辨率、眼镜/光照、真实端到端响应和至少4人表现仍需实际摄像头测量。没有这些数据时，不声称精度已提升或关闭M2。
