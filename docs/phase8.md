## 用户授权与实现

用户要求继续降低五点验证、屏幕内外等门槛，并允许未达标进入游戏。使用同一模型与15项位置/10项屏幕校准；独立五点和10项屏幕验证保留，验证样本不参与拟合。本轮未改变采样数量、稳定样本要求、Worker、共享 AttentionPort 或 B 的场景/游戏源码。

| 策略 | Phase 7 easy-entry-v1 | Phase 8 easy-entry-v2-phase8 |
| --- | --- | --- |
| 位置有效采样率 | ≥70% | ≥50% |
| 中位误差 / P90，屏幕对角线比例 | ≤15% / ≤25% | ≤25% / ≤40% |
| 屏内/外误报，各自比例 | ≤20% | ≤35% |

| 屏内/外分类分数 | ≥0.55 / ≤0.45 | ≥0.52 / ≤0.48 |

配置集中于 `src/attention/entry-policy.ts`；位置报告从同一配置生成阈值文字，CSV 继续写入策略版本。全无效、反向状态和无数据仍报告未通过；本轮没有降低原 M2 真人验收标准或宣称达到它。

连续引导在五点验证失败后继续屏幕校准与验证，不再强迫重试。只要摄像头开启、处于全屏且两种校准模型已成功建立，就可点击“未达标或未验证，仍进入徒步”。不自动进入；点击只设置当前会话的 `unverifiedEntry`，不把 `positionVerified` 或 `screenVerified` 改成 true。已完成两种校准但跳过独立验证时也可选择体验入口。

`CameraAttention` 和纯决策流水线分别检查运行条件与模型/验证状态；进入同一真实眼动徒步流程，支持默认首页、组合森林页和三目标诊断。首页组合层与森林组合层显示持续的“体验模式”提示。没有伪造通过报告或将估计坐标裁剪以缩小误差。

## 失效与边界

“验证未达标”不同于无法生成模型。拒绝摄像头、位置拟合失败、屏幕分类模型未生成或退出全屏时仍需要恢复基础条件。完全没有摄像头数据无法驱动眼动；可从首页使用既有鼠标/键盘探索入口。

进入后仍需有效实时输入才可开始行走。闭眼、无人脸、过期帧、后台、离屏、坐姿越界和暂停不产生有效行走样本。重新校准或验证撤销本次体验授权；停止摄像头、显示区域变化、清除校准也清除授权。验证失败原样保留，用户可以重新验证或再次选择继续进入。

放宽阈值与失败后继续会增加方向误差、误走或离屏误判。历史汇总结构未修改，因此跨版本/体验模式记录不能作为精度提升证据；校准参数及授权不持久化。
