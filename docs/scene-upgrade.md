## 版本定位

原自动游览初版正式命名为“框架场景1.0”。原始截图、视频和测量保留在 [v0.1](acceptance/v0.1/README.md)，对应历史 PR 提交，不混入本次效果。当前仍属于框架的探索迭代，不能标记为最终场景、写实达标或阶段完成。

## 视觉和体验方向

参考《猎人：荒野的召唤》的自然环境观察与探索：远景地形、中景林冠、近景树皮／岩石／林下植物；路段在封闭林地、溪岸与开阔山坡之间变化。借鉴环境构成，不复制模型、纹理、截图或 UI。[官方探索开发日志](https://callofthewild.thehunter.com/developer-diary-exploring-emerald-coast/)与[官方 Revontuli Coast 环境介绍](https://callofthewild.thehunter.com/home/dlc/reserves/thehunter-call-of-the-wild-revontuli-coast/)为方向来源。Blender Eevee 对照和浏览器实际画面共同审阅；游戏名不能替代可检查的标准。

同一地图设置溪谷主路、苔岩环线、山坡观景路，连接两处主路节点，允许往返。森林密度有疏密变化，留下路径、溪流和观景空隙。真实叶片纹理和蕨类替换纯色占位植物，增加岩石、倒木、根系。行走速度以 1.45m/s 为起点；镜头高度约 1.7m，随路面高度变化，不以持续镜头抖动制造徒步感。

## 提高后的验收

- [ ] **自由观察**：开始后拖动可转满一周、抬头／低头；归正后朝向恢复。切后台或松开输入停止操作。暂停时位置不变，仍可观察。
- [ ] **连通路线**：三条可辨认小径，至少一个可往返环线。实际从营地走入两条支路并返回，目的地自动移动沿路径图，不能直线穿林、穿桥或传送。重复选择不产生重复动画循环。
- [ ] **路况和徒步**：路线含上坡、下坡、溪桥及山坡观景点；主路与观景段相对高度变化至少 5m。人物视点在地面／桥面上方约 1.7m，无明显穿地、悬浮和越过树干／大石。WASD 移动能停下、回头与倒退。
- [ ] **场景层次**：营地、林地、溪流、山坡四个固定视角，每处截图能指出前中远景；近景有树皮／叶片／石块纹理，路径边缘自然过渡。30～60 秒视频检查叶片闪烁、穿模、阴影变化。新增景物数量不是画质通过的依据。
- [ ] **写实画质**：前三处输出相同镜头、1920×1200 Eevee 与浏览器对照；用户明确确认自然尺度、植被形态、PBR、阴影、色调与纵深达到约定风格。当前未通过，待审阅项不得打勾。
- [ ] **性能和失败**：相同画质记录真实 GPU、分辨率、首次／缓存加载、60 秒有效行走帧时间和 P95；目标单场景 60FPS，后续联合稳定 30FPS 底线不变。资源加载失败给原因和重试，完整自动游览、暂停 10 秒、重启三次仍通过。
- [ ] **真实眼动**：用户已选择“注视地点后自动走过去”。使用现有 TargetRegion/GazeEvent，对四个大目的地停留确认后移动；移动中锁定新选择，到达重新开放。camera 来源有效、近期样本才允许确认；模拟或手动操作不能代替此项。A 完成真实识别并交叉审查后，做实际摄像头选择与误触发测试。

## 文件、接口与交接

B：`src/scene/build_forest.py` 制作地形与资产，`src/scene/forest.ts` 渲染／视角／地面检测，`src/game/navigation.ts` 路径图与步行，`src/game/app.ts` 操作与目的地 UI。测试见 `tests/navigation.test.ts` 与浏览器探索检查脚本。

`mountGame(app, attention?)` 可消费现有 AttentionPort：订阅真实样本／确认事件，把目的地按钮投影为现有 TargetRegion。无新增共享字段。当前启动入口不传模拟源，因此真实眼动尚未启用；A 在真实识别可用后完成入口接线与契约消费审查。仅支持预定义地点的注视选择，任意地面像素的真实眼动寻路尚未实现，需双方明确投影与误触发策略后接入。

顺序：命名并记录不通过 → 连通路况与自由镜头 → 真实纹理与环境层次 → 浏览器功能／性能记录 → 四视角人工审阅 → A 真实眼动接线及联合测试。保持 B 草稿 PR，真人交叉审查后合并；不关闭 M1。
