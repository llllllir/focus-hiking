# Focus Hiking：Phase 1 优化计划

状态：用户已确认开发方向；应用尚未实现，视觉、性能与联合验收均未通过。

## 1. 八格 spec

| 格子 | 项目内容 |
| --- | --- |
| 项目名 | Focus Hiking：森林登山体验 |
| 目标用户 | 一位长期坐在电脑前办公、希望在工作间隙体验自然环境的成年人 |
| 当前困难 | 工作间隙仍停留在电脑前，缺少可直接进入、流程简单的森林体验；不将此描述为已验证的健康需求 |
| 只做的一件事 | 打开电脑网页，完成一次具有 Blender Eevee 写实视觉水准的森林自动游览 |
| 用户流程 | 打开页面 → 点击开始 → 沿营地、小径、溪流自动游览 → 随时暂停或重启 → 到达终点 |
| 验收标准 | 以下三组检查全部完成，保留实际运行证据 |
| 明确不做 | 多地图、自由漫游、真实摄像头识别、训练反馈、LLM、动态昼夜、实时路径追踪和复杂体积效果 |
| 技术约束 | TypeScript + Vite + Three.js；Blender 制作与烘焙，导出浏览器资源；保留 A/B 模块边界、现有接口和性能要求 |

附件用于借鉴 spec 与设计文档结构，秦宫编钟的功能、音乐及技术决策不进入本项目。

## 2. 视觉规范与制作流程

视觉基准采用 Blender Eevee 写实实时效果。浏览器效果须实际比对，不能因资源来自 Blender 就宣布达到标准。[Blender 官方说明](https://developer.blender.org/docs/features/eevee/)

- 根目录 DESIGN.md 统一初夏山地混合林、柔和日间侧光、自然尺度、薄雾和固定曝光，明确材质、镜头与界面规范。
- refs/ 保存 3～5 张可合法收录的森林视觉参考及来源说明，每张标注借鉴内容；方法资料不是画质参考。
- Blender 制作同一地图的营地、小径、溪流和远山；先完成一段林间路径样片，用户审阅后扩展整条路线。
- 使用自然比例、PBR 地表、树皮与岩石材质；植被按群落分布，大小、朝向和间距有变化；近景细节优先，远景降低复杂度。
- 烘焙程序材质、法线及 AO；静态间接光采用独立 lightmap，由 Three.js 显式接入。直接日光与主要阴影由浏览器计算，避免重复烘焙同一光照。导出后检查完整材质与效果，不假定 glTF 自动保留 Blender 节点。[Blender glTF 文档](https://docs.blender.org/manual/en/3.3/addons/import_export/scene_gltf2.html)
- 交付可编辑 Blender 工程、导出资源及来源记录，核对仓库存储规则与文件大小后提交。

界面默认值：深色半透明底板、浅色文字、苔绿强调色；系统中文无衬线字体；正文/按钮 16px、标题 24px；8px 间距基准；按钮过渡 150ms；稳定前进镜头，不持续摇晃。

不要做：低多边形卡通树、统一纯绿、塑料高光、均匀树阵、浓雾遮丑、强 Bloom、夸张景深、紫色渐变界面和 emoji 图标。

## 3. 实施顺序与接口

1. 核对角色、M1 Issue、远端 main 和本地变更；不在同一目录同时运行 A/B agent。
2. A 建立启动入口、共享类型、场景挂载边界及实际检查脚本，由 B 审查基础 PR。
3. B 完成参考板、路线灰盒、Blender 样片和浏览器导入，保存同场景 Eevee/浏览器对照。
4. B 将审阅标准扩展到营地、溪流和整条路线，实现自动游览、暂停、恢复、重启以及失败提示和重试。
5. A 完成明确 simulated 的诊断，B 完成视觉、性能、演示记录；各自 PR、交叉审查，导师确认后关闭 M1。

GazeSample、TargetRegion、GazeEvent、SceneEvent、TrainingCommand 保持现有契约，不新增公共字段。Blender 资源加载、lightmap、画质配置属于 B 内部实现；工程依赖和锁文件由 A 维护。

保留 spec.md → plan.md → tasks.md；视觉方向文档作为补充。AGENTS 增加场景/界面修改前阅读 DESIGN、参考记录与不要做清单的规则。

## 4. 三组验收标准

- [ ] 完整流程：新环境按说明启动；开始后经过营地、小径、溪流并到达终点；暂停 10 秒位置不变，恢复连续；连续重启三次回起点，无重复动画循环。加载或 WebGL 失败显示原因与可用重试入口。
- [ ] 视觉对照：营地、小径、溪流各保存相同镜头 1920×1200 Eevee/浏览器截图，检查比例、材质、接地阴影、植被层次、纵深及路标可读性。用户确认三组达到基准；视频无明显穿模、闪烁或阴影跳动。参考图与离线成片不能代替运行截图。
- [ ] 可复现交付：实际安装、类型检查、构建及必要测试；浏览器、GPU、加载耗时、画质、FPS；30～60 秒运行视频、素材许可、未解决项；双方 PR 审查与导师验收。

## 5. 默认值与边界

Phase 1 = M1 / v0.1，交付整条初步路线，样片为中间检查点。内部渲染最大 1920×1200、DPR ≤1.25；场景单独争取 60FPS，后续联合稳定 30FPS 门槛不降低。

先优化复用、实例化、距离分级、透明叶片重叠和阴影范围；优化后重新视觉对照。不能兼顾画质与性能时记录冲突，由负责人决定。

Blender 级效果以用户审阅通过的三组对照落实，不承诺渲染器逐像素一致。共享计划不代表功能完成，不关闭任何阶段 Issue 或 Milestone。
